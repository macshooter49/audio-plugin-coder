v14 — Wavetable Engine 5-knob rework

Synthesis of Serum 2 (dual warp) + Vital (spectral morph axis + frame spread) + Pigments (wavefolding as a headline section). Front: 5 wavetable-engine-specific knobs that each move the sound day-and-night. Back (toggled via +): the type-selector zone replaces the visualizer + the 5 tuning knobs return underneath.

The locked v12 OSC A device frame stays — same width, same height, same colors, same engine pills row. Only the contents of the visualizer area and the knob row change between front/back states.

Variant A (Recommended) — SPREAD on the OSC device

Five front knobs: WT POS · WARP · SPECTRAL · FOLD · SPREAD. PHASE lives on the back panel as a small modifier next to the tuning row. SPREAD is the per-OSC frame spread (Phase 8b architecture: each unison sine plays a different wavetable position — Vital's frame_spread idea, now uniquely ours because of T1-T9). Each OSC gets its own SPREAD value so OSC A can be tight while OSC B fans wide.

Back view: 4 type-selector dropdowns replace the visualizer. WARP + SPECTRAL + FOLD set the modes for the three transformation amount knobs on the front. The 5 tuning knobs (OCT/SEM/CENT/PAN/LEVEL) sit underneath — exactly the original v12 row. PHASE init + RAND lives in a right-click menu on WT POS to save space.

Variant B — SPREAD in VOICES META column (alternative)

Same front: WT POS · WARP · SPECTRAL · FOLD · PHASE — PHASE replaces SPREAD as the 5th front knob. SPREAD moves to the VOICES META column on the right (next to UNISON / SPREAD-pan-detune / EROSION / HORIZON / VOICES). Pros: PHASE is more accessible. Cons: one VOICES META row gets crowded; FRAME SPREAD becomes a single global value not per-OSC.

Why Variant A wins (my call)

SPREAD per-OSC is more useful than PHASE on the front for three reasons:

  1. Sonic impact: SPREAD at UNISON=8 is genuinely day-and-night. PHASE init mostly affects the first 5ms of a note. SPREAD is "what does this sound like at all"; PHASE is "what does the very first instant sound like."
  2. Per-OSC value matters: SPREAD per-OSC = OSC A can sit tight while OSC B fans wide across the wavetable. Way more interesting than one global SPREAD value.
  3. PHASE doesn't get lost on the back: Right-click menu on WT POS exposes PHASE init + RAND amount. Users who want it find it; users who don't aren't paying for it with knob real estate.

Signal chain (DSP order, locked by the front-back design)

WT POS → WARP (phase-domain) → SPECTRAL (freq-domain) → FOLD (post-spectral harmonic generator) → per-sine sum → filter → HORIZON → output

This matches Pigments' chain (Position → FM/PM → Phase Transform → Wavefolding → Output) and works with Phase 10a (spectral content is already in FrameSpec) + Phase 8b (per-sine sum is where SPREAD applies). Three transformation axes (WARP / SPECTRAL / FOLD) — each independent — give the sound designer a real 3D timbral space. None of the three references has all three on the front simultaneously.

Implementation phases that fall out of this design:

Phase 11b: Expand WARP modes (add Pigments Phase Transform set + Serum FM/RM/PD source variants).
Phase 11c: SPECTRAL MORPH DSP (apply transformations to FrameSpec at noteOn — uses Phase 10a frequency-domain spec).
Phase 11d: WAVEFOLDING DSP (post-spectral harmonic generator).
Phase 11e: Per-engine front-panels for FM/NOISE/SAMP/GRAN/SPEC (each with its own 5 engine-specific knobs).
