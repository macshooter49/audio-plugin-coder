Reader report, 2026-09-02. Source root: `plugins/TerrainInstrument/Source` (worktree `terrain-instrument`). JUCE the build links: `_tools/JUCE` = **8.0.12** (`modules/juce_core/system/juce_StandardHeader.h:42-44`, checkout `501c07674e`, 2026-01-16). Every code claim below is `file:line`; every external claim carries its URL. No source file was edited.

## 0. TL;DR

- **Today** the wheel / aftertouch / bend are ONE global value each: `processBlock` walks the buffer once and the last message of any channel wins (`PluginProcessor.cpp:7915-7926`), smoothed 10 ms (`:7928-7931`) into `wc::GlobalModSources` (`SynthModConfig.h:1126-1133`), read by every voice through `gsrc_` (`SynthVoice.h:426-429`). Poly pressure is folded into the same global aftertouch (`PluginProcessor.cpp:7925`). Bend is hard-wired to every oscillator's COARSE lane (`SynthVoice.h:3310-3315`). The AU does **not** declare MPE — there is no `supportsMPE()` override anywhere in `Source/` (only `acceptsMidi`, `PluginProcessor.cpp:12859`), so JUCE's AU wrapper answers `kAudioUnitProperty_SupportsMPE = 0` (`_tools/JUCE/modules/juce_audio_plugin_client/juce_audio_plugin_client_AU_1.mm:604-606`).
- **The good news:** `juce::Synthesiser` — which `UnisonSynth` subclasses (`PluginProcessor.h:165`) — is already channel-aware end to end: a voice remembers its channel (`juce_Synthesiser.cpp:341`), note-off matches note **and** channel (`:372-373`), a second note-on of the same number on a different channel does not stop the first (`:320`), and pitch-wheel / channel-pressure / CC are dispatched per channel to `SynthesiserVoice::pitchWheelMoved` / `channelPressureChanged` / `controllerMoved` (`:403-447`) — which `SynthVoice` currently overrides as empty (`SynthVoice.h:2943-2944`). So MPE is mostly *state plumbing*, not a voice-allocator rewrite.
- **The design** (§4): a Settings toggle `SYN_MPE_ON` (+ RPN 6 auto-arm), `supportsMPE() = true`, per-channel `bend[17] / pressure[17] / slide[17]` + per-note `polyAt[128]` in `GlobalModSources`, a voice that captures its channel at note-on via a staged atomic (the fb122 `robinStage` pattern, `PluginProcessor.h:229` → `SynthVoice.h:2713-2720`), a new appended `ModSource::Slide` on wire **245** (244 = Alt is the last taken code, `SynthModConfig.h:1100`), the bend evaluator becoming `master × SYN_BEND_RANGE + member × SYN_MPE_BEND(48)`, and a sustain / all-notes-off fan-out from the master channel. Non-MPE mode stays byte-identical except that poly pressure becomes per-note (the point of the feature).
- **Host reality** (§2): in Ableton Live the **AU** is the path — JUCE 8.0.12's VST3 wrapper drops note-expression events (`juce_VST3Common.h:1533-1537`) and never implements `IVst3WrapperMPESupport` (grep: zero hits in the wrapper; the interface exists only in the bundled SDK). The JUCE forum documents exactly this: a JUCE VST3 "handles MPE correctly in Bitwig but fails in Ableton and Cubase on macOS" (https://forum.juce.com/t/audioprocessor-supportsmpe-missing-on-vst3/44347). Live "will configure itself for VST2 and AU plug-ins that self-identify with MPE support" (https://cdm.link/these-instruments-work-with-mpe-right-away-for-an-expressive-ableton-live-11-launch/), and any plug-in can be forced with right-click title bar → **Enable MPE Mode** (https://help.ableton.com/hc/en-us/articles/360019144999-MPE-in-Live-11-and-later-FAQ; manual §12.5/12.6 https://www.ableton.com/en/live-manual/12/editing-mpe/).
- **PolyBrute 12** (§2.2): Settings → MIDI → MPE = Off / Receive / Send / Both; MPE Bend Range 2…96, **default 48**; Channel Count; Single-timbral mode = MPE **Lower Zone** (master ch 1, members from ch 2); "When sending MPE, PolyBrute 12 sends mono aftertouch (Channel Pressure) and Slide (CC74) on multiple channels (one per note)". In NON-MPE mode the Aftertouch button's **Mono** = Channel Pressure, **Poly** and every FullTouch mode = **Polyphonic aftertouch** (0xA0). Mod wheel = CC 1, Ribbon = CC 9, Morphée X/Y/Z = CC 114/115/89 (manual §13.1). Source: the v3.1.3 manual PDF, https://dl.arturia.net/products/polybrute-12/manual/polybrute-12_Manual_3_1_3_EN.pdf.
- **Size:** ~550-650 lines across 9 files + a ~300-line `Tests/mpe_cert.cpp` (§6). Biggest risk is not code — it is whether Live actually delivers channel-rotated MIDI to the AU once `SupportsMPE` flips (§7, and Max can pre-test that today, §8.4).

## 2. External facts (cited)

### 2.1 The MPE spec (MMA v1.0, 2018-03-12) — https://d30pueezughrda.cloudfront.net/campaigns/mpe/mpespec.pdf
- Lower Zone = Master Channel **1**, Members assigned upward from **2**; Upper Zone = Master **16**, Members downward (§2.1.1). Zones are set by the **MPE Configuration Message = RPN 6** on the master channel; "Sending an MCM with the number of Member Channels set to zero deactivates that Zone."
- "Pitch Bend is, by default, set to a range of **±48 semitones for per-note bend and ±2 semitones for Master bend**. Either range may be changed … using RPN 0" (p.1). "When a receiver receives an MPE Configuration Message, it must set the Master Pitch Bend Sensitivity to ±2 semitones, and the Pitch Bend Sensitivity of the Member Channels to ±48" (§2.4). RPN 0 on the master sets master range; RPN 0 on any member applies to **all** members of the zone. "If a device receives Pitch Bend on both a Master Channel and Member Channel, it must combine such data meaningfully and separately for each sounding note" (§2.4).
- "Aftertouch is sent using the Channel Pressure message … Polyphonic Key Pressure may be used with notes on the Master Channel, but not on other Channels" (p.1); "Polyphonic Key Pressure must not be sent on Member Channels" (§2.5). Master + member pressure must be combined per note (§2.5).
- "This additional dimension is mapped to Control Change #74. All MPE receivers are required to respond to CC #74 at the Zone and Note level" (§2.6).
- Note-on/off happen on the member channel; the same Note Number may be active on two channels ("a note may start at a certain pitch and be bent to another before a second note is initiated at the original pitch", §3.2). Notes on the master channel are permitted and must sound (§3.2).

## 4. The design (against this code)

### 4.1 Declaration and the mode switch
- `PluginProcessor.h` next to `acceptsMidi` (`:569`): `bool supportsMPE() const override { return true; }` — constant, as the JUCE doc demands. Effect: AU `kAudioUnitProperty_SupportsMPE = 1` (`AU_1.mm:605`), VST2 `canDo("MPE")` (`VST2.cpp:1877`), AUv3 (`AUv3.mm:416`). VST3 unaffected (§1.5).
- New params (in `createParameterLayout` beside `SYN_BEND_RANGE`, `PluginProcessor.cpp:4409`): `SYN_MPE_ON` (`AudioParameterBool`, default **false**) and `SYN_MPE_BEND` (`AudioParameterFloat` 0..96 step 1, default **48**). IDs in `ParameterIDs.hpp:550`'s neighbourhood.
- Effective mode on the audio thread: `mpeOn_ = SYN_MPE_ON || mcmArmed_`, where `mcmArmed_` is set when an **RPN 6** (CC101=0, CC100=6, CC6=n) lands on channel 1 or 16 with n>0 and cleared with n=0 (spec §2.1.1) — so a host or controller that speaks the spec engages it without a click, while a plain keyboard on channel 2 does not. Do **not** auto-detect from "note on channel ≥ 2": that is exactly a PolyBrute in non-MPE mode with Output Channel set to 2, and it would silently switch its bend range from 2 to 48. Show the live state in Settings ("MPE · Off / On" buttons + a small "armed by host" tag).
- Zone: `wc::MpeZone { int master = 1; int memberLo = 2, memberHi = 16; bool upper = false; }` in `SynthModConfig.h`, defaulted to Live's and the PolyBrute Single-mode layout; RPN 6 updates it. (`juce::MPEZoneLayout` from `juce_audio_basics/mpe/` can do the bookkeeping, but a 4-int struct is enough and JUCE-free for the shim-built tests.)

### 4.2 Per-channel state (the processor walk, `PluginProcessor.cpp:7915-7935`)
Extend `wc::GlobalModSources` (`SynthModConfig.h:1126`) — append, never reorder:
```
std::atomic<float> chBend[17], chPressure[17], chSlide[17];   // index = MIDI channel 1..16, 0 unused
std::atomic<float> polyAt[128];                                // note-keyed poly pressure (non-MPE per-note)
std::atomic<float> slide { 0 };                                // global CC74 (non-MPE / master)
std::atomic<float> mpeBendRangeSemis { 48.0f };
std::atomic<int>   mpeOn { 0 }, mpeMaster { 1 }, mpeMemberLo { 2 }, mpeMemberHi { 16 };
std::atomic<int>   pendingNoteChannel { 1 };                   // staged by UnisonSynth::noteOn, taken by startNote
```
The walk keeps its shape (one pass, targets, 10 ms one-pole at block rate, `:7928`) but becomes channel-aware:
- `isPitchWheel`: if `mpeOn && ch` is a member → `bendT_[ch]`; else → `midiBendT_` (master / non-MPE, **unchanged path**).
- `isChannelPressure`: member → `atT_[ch]`; else → `midiAtT_` (unchanged).
- `isAftertouch` (poly): `polyAtT_[note]` **and**, for byte-identity of the global half, still `midiAtT_` as today (`:7925`).
- `isController`: CC1 as today; **CC74** → member → `slideT_[ch]`, else `midiSlideT_`; `midiCcSeen` only for master-channel / non-MPE CCs so a member CC74 stream cannot thrash a learned knob (`midi_learn_cert.cpp` bar 5 is the precedent that CC1 may be both).
- RPN parse (CC101/100/6/38 per channel, tiny state machine): RPN 6 → zone + `mcmArmed_`; RPN 0 on the master → nothing (Settings owns `SYN_BEND_RANGE`) or optionally override; RPN 0 on a member → `mpeBendRangeSemis` for all members (spec §2.4).
- Sustain / all-notes-off fan-out: when `mpeOn` and a CC64 / CC123 / CC120 arrives on the master, `UnisonSynth` (override `handleController`/`handleSustainPedal` or pre-expand the buffer) applies it to every member channel, because `juce::Synthesiser` filters by `isPlayingChannel (midiChannel)` (`juce_Synthesiser.cpp:460-490`).
- Smoothing cost: 3 × 16 + 128 one-poles per block — negligible; only channels that received a message need updating (keep a `dirty` bitmask), everything else decays toward its target exactly as today.

### 4.3 The voice knows its channel
`SynthesiserVoice::currentPlayingMidiChannel` is private (`juce_Synthesiser.h:282`), so stage it the way fb122 stages a Robin hit (`UnisonSynth::robinStage`, `PluginProcessor.h:229` → `takeHit` in `startNote`, `SynthVoice.h:2713-2720`): `UnisonSynth::noteOn` (`:181`) and both mono paths (`:346, :383`) store `gsrc->pendingNoteChannel = midiChannel` **before** the base call (all under the synth lock, so no race); `SynthVoice::startNote` (`:2724`) captures `channel_ = gsrc_->pendingNoteChannel` beside `currentMidiNote_`. The legato-retarget branch (`:2673-2708`) also refreshes `channel_`. Alternative with zero staging: override `pitchWheelMoved / channelPressureChanged / controllerMoved` (`:2943-2944`) and keep per-voice targets — JUCE already routes them by channel (`juce_Synthesiser.cpp:403-447`) — but then the processor's global (rack) half and the comet feed would need a second source of truth; the atomics-in-`GlobalModSources` route keeps ONE reader (`sourceValueOf`, fb563 (3)'s law).

### 4.4 The readers (`sourceValueOf`, `SynthVoice.h:416-432`)
```
Aftertouch: mpeOn && isMember(channel_) ? max(chPressure[channel_], polyAt[note])   // MPE: per-note pressure
          : max(aftertouch /*global, as today*/, polyAt[currentMidiNote_])          // non-MPE: poly AT keyed by note
Bend      : mpeOn && isMember(channel_) ? clamp(bend + chBend[channel_])            // master + member, −1..+1 as a SOURCE
          : bend                                                                    // unchanged
Slide     : mpeOn && isMember(channel_) ? chSlide[channel_] : slide                  // NEW source
Wheel     : unchanged (CC1 is zone-wide; spec §2.7 leaves it to the master)
```
Byte-identity in non-MPE mode: with only channel pressure on the wire, `polyAt[]` is all zero and `max(global, 0) == global` exactly. With poly pressure, today a voice sees *the last poly AT of any key*; after this it sees *its own key* — the intended behaviour change and the only one.

`sourceValueOfSrc` (`PluginProcessor.cpp:13352`) gets the same three cases with the **most-active-voice law** for the per-note half (`randVis_`/`altVis_`, fb563): the voice pass that already picks `bestVoice` (`:10686-10700`) publishes `atVis_`, `bendVis_`, `slideVis_` from `bestVoice->sourceValueOf(...)`, and the global pass (`:8597-8604`) reads those when `mpeOn` (global values otherwise). The editor push (`PluginEditor.cpp:5965-5967`) gains `__mvSlide` and, in MPE, feeds `__mvAT/__mvBend` from the same vis atomics so the comets follow the finger.

### 4.5 The hard-wired bend (`SynthVoice.h:3313`)
```
const float bendSemi = gsrc_->bend.load() * gsrc_->bendRangeSemis.load()                       // master × SYN_BEND_RANGE (unchanged)
                     + ((mpeOn && isMember(channel_)) ? gsrc_->chBend[channel_].load() * gsrc_->mpeBendRangeSemis.load() : 0.0f);
```
In non-MPE the added term is exactly `0.0f` → identical arithmetic. This honours spec §2.4 ("combine … separately for each sounding note"). `ModDest::Pitch` still has no voice case (fb568 note) — untouched here.

### 4.6 The new source: `Slide` (CC74)
Append-only, the fb563 law; wire codes taken: 220-228 (Macro 1-9), 229 free-by-design, 230-232, 240-244 (`SynthModConfig.h:1095-1100`). **`kSlideSrc = 245`**, `ModSource::Slide` appended after `Alt` (`:56`, before `NumSources`).
- C++: `phase2SourceForWire` (`:1114-1123`) maps 245; `isUniAdditiveSource` (`:1105-1109`) includes it (unipolar 0..1, signed depth — the Velocity law, like Aftertouch); `isBlockConstantSource` follows automatically (`:1111`); `sourceValueOf` (§4.4), `sourceValueOfSrc`, the global pass (`:8597-8604`) and the LfoAmt pre-pass (`:8517`, via `globalSourceValue`) — the fourth site the gate counts (`mod_source_gate.py:97-100`) is already generic through the helper. `fxmod_cert.cpp:126-128` sizes its fake-rack arrays by `NumSources`, so it just grows — re-run it.
- JS (`index.html`): `WIRE.SLIDE:245` (`:31182`); `encodeSrc` `a.sld?WIRE.SLIDE` (`:31185`); `decodeSrc` `if(sv===WIRE.SLIDE) return {sld:1}` (`:31186-31198`); `SRC_KEYS` add `'sld'` (`:31199` — "a new family is one word here"); `srcTag` `'sld'` (`:31202`); `srcName` `'Slide'` (`:31554`); the picker's MIDI family `mk({sld:1},'Slide')` (`:31728`); `p2v` `if(a.sld) return … __mvSlide` (`:31971`) and the `__mvP2Tick` snapshot (`:31961`); `isMagnitudeSrc` unchanged (signed). Popped-card pass-through is generic from `kVelSrc` (`mod_source_gate.py:79-84`).
- Gate: `Tests/mod_source_gate.py` must learn `kSlideSrc` in the helper-token list (`:90`), `('SLIDE','kSlideSrc')` in `PAIRS` (`:48-50`), `WIRE.SLIDE` in the encoder list (`:57`), a `sv===WIRE.SLIDE` decode check, and `wc::ModSource::Slide` in the `SynthVoice` tokens (`:99`). Also its mutation control.

### 4.7 Settings UI (`index.html:5940-5966`)
Two rows after the bend row: **"MPE"** with `Off` / `On` buttons (the Theme two-button pattern, `:5948-5955`) writing `__setSynParam('SYN_MPE_ON', 0|1)` and seeded on the [0, 900, 2500 ms] ladder like `seedB` (`:12646-12648`); **"MPE bend range · 48 st"** cloning the `rr-bend-row` drag/double-click code (`:12643-12660`), double-click = 48. Settings is a free-height overlay, so the fb563 fixed-positions trap (voice column) does not apply.

### 4.8 Voice allocation in MPE
Already correct in JUCE: note-off matches channel (`juce_Synthesiser.cpp:372-373`), same-note-different-channel does not retrigger (`:320`), `UnisonSynth`'s cap steal is channel-blind by design (oldest note wins, `PluginProcessor.h:200-226`). Two things to add: (a) the ARP path (`PluginProcessor.cpp:10617-10632`) rewrites to channel 1 — in MPE either carry `m.getChannel()` for the dry notes and accept master-only expression for arp-generated notes, or document "ARP ⇒ master-zone expression"; (b) the note-keyed side walks (`resoHeld_ :7951`, `fltPool_.noteOn :10620`, `synthNotesHeld_ :9818`) may drop a held note early when the same number is released on another channel — cosmetic (annulus tuning / key-track), noted, not fixed.

### 4.9 The regression law (what stays byte-identical with `SYN_MPE_ON = 0` and no MCM)
- Channel pressure, CC1, pitch wheel, `SYN_BEND_RANGE`: same targets, same one-pole, same stores (`:7918-7935`); bend evaluator adds a literal `0.0f`.
- Voice allocation untouched; `pitchWheelMoved/controllerMoved` stay empty.
- The only delta: poly pressure per note (§4.4), and CC74 becoming a source **in addition to** MIDI Learn. `mod_src_cert.cpp` (11/11), `filter_mod_cert.cpp` (9/9), `midi_learn_cert.cpp` (7/7), `fxmod_cert.cpp`, `fb563_menu.js`, `mod_source_gate.py` re-run green = the proof.

## 7. Risks

1. **Live + AU delivery** — the biggest unknown: does Live rotate channels into the AU once `SupportsMPE` = 1 (CDM says it "configures itself"), and does the manual **Enable MPE Mode** already do so today? Max can answer both before any code (§8.4). If Live sends poly-AT-converted MPE for the PolyBrute's Poly mode (forum thread), the plug-in sees channel pressure on members — covered.
2. **VST3 in Live**: JUCE 8.0.12 has no `IVst3WrapperMPESupport` and drops note expression (§1.5) → ship the AU story; VST3 is "works in Bitwig, unverified in Live".
3. **Auto-detect false positives** — hence RPN 6 only, never "note on ch ≥ 2".
4. **ARP + MPE** and the note-keyed side walks (§4.8).
5. **MIDI Learn thrash** from member-channel CC74/CC1 — gate `midiCcSeen` to master/non-MPE.
6. **Sustain / all-notes-off per channel** in JUCE (§4.2) — without the fan-out, a pedal on the PolyBrute holds nothing.
7. **Enum append** grows `NumSources` — `fxmod_cert.cpp` arrays resize themselves; any hard-coded `245` elsewhere would be a fifth door — `mod_source_gate.py` is the guard.
8. **Global-half semantics** (most-active voice) for Aftertouch/Bend/Slide in the rack — a design choice, document it in the memory note.
9. **`startNote`'s ignored `pitchWheelPos`** (`SynthVoice.h:2663`) — the per-channel smoothed state already carries the bend a controller sends before note-on, but if a member channel was silent for a long time its smoothed value equals its target, so no slew artefact; verify in bar 2 by bending *before* the note-on too.
10. **PolyBrute wheel channel in MPE Send** — if the wheel rides the member channel rather than master, master bend is simply never seen; harmless.

## 8. WHAT MAX CAN TEST TODAY (before MPE) — PolyBrute 12 → Ableton Live (Mac) → Terrain (AU)

### 8.1 PolyBrute 12 (non-MPE, everything global)
1. **Settings → MIDI → MPE → Off** (manual §12.8.8) — leave MPE for §8.4.
2. **Settings → MIDI → Channels → Output Channel (upper)** = 1 (§12.8.1); Local control as you like.
3. **Settings → MIDI → Enable CC on Knobs = ON** (§12.8.7) — the mod wheel then sends **CC 1** (§13.1); ribbon CC 9, Morphée X/Y/Z 114/115/89 are learnable via the plugin's MIDI Learn (fb563 (4)).
4. **[Aftertouch] button → Mono** (§5.4.5) — the keys send **Channel Pressure** (§12.4.3.2 table, "Mono AT / Non MPE / Channel Pressure"), which is the value the plugin reads at `PluginProcessor.cpp:7924`. In **Poly** (or any FullTouch mode) the keys send **polyphonic aftertouch** (0xA0), which today is folded into the same global at `:7925` — last-pressed-key-wins for *every* note. Both work; Mono is the honest test of the global source, Poly demonstrates the gap this design closes.

### 8.2 Ableton Live
1. **Live → Settings → Link, Tempo & MIDI**: for the PolyBrute 12 input port set **Track = On** (Remote off so CC1 is not eaten as a remote mapping; **MPE off** for this test). (https://help.ableton.com/hc/en-us/articles/209774205-Live-s-MIDI-Settings)
2. MIDI track: **MIDI From = PolyBrute 12**, channel **All Channels** (or Ch. 1); **Monitor = In** (or Auto + arm). Insert **Terrain Instrument (AU)** — the AU is the format the certs and this design target.
3. Live 11+ forwards **channel pressure and poly aftertouch** to plug-ins (Live 10 filtered poly AT — https://forum.ableton.com/viewtopic.php?t=244043); pitch bend and CCs pass as ordinary MIDI. Nothing else to enable.

### 8.3 Terrain gestures (fb563 / fb568)
- **Aftertouch → any knob**: right-click the knob → **Modulate** → family **MIDI** → **Aftertouch** (double-click assigns and closes; `index.html:31728`). Depth slider is signed (Velocity law: pressure 0 leaves the knob alone; at depth −1 it turns it down). Try Level A at 0 with depth +1 — sound only under pressure (`mod_src_cert` bar 4's exact law).
- **Aftertouch → filter cutoff** (fb568): the filter does nothing until (1) a filter **TYPE** is chosen (default NONE) and (2) the oscillator is **sent** into it (the **F1 pill / `SYN_OSC_A_F1MIX`**, default 0 = dry). Then right-click Cutoff → Modulate → MIDI → Aftertouch. `filter_mod_cert.cpp` proves this path 9/9.
- **Mod wheel**: Modulate → MIDI → Mod Wheel (CC 1). Learned CC1 on a knob still drives the wheel source (`midi_learn_cert` bar 5).
- **Pitch bend**: hard-wired, nothing to route; **Settings (gear) → "Pitch bend range · 2 st"** — drag the number, double-click = 2 (`index.html:5958`). Match the PolyBrute's own bend range (Settings → Expression Control → Bend Range, manual p. 4808 shows "1 Semitone" as a preset value) so the analog and the plugin bend together. Expected: 261.5 → 293.5 Hz at range 2 on a full bend (`mod_src_cert` bar 5).
- **Poly aftertouch reality check**: in [Aftertouch] = Poly, hold a chord and press ONE key — every note in Terrain reacts (global). That is the "before" for this design.

### 8.4 The MPE dry run Max can do today (answers risk #1 before any code)
1. PolyBrute: **Settings → MIDI → MPE = Send** (Channel Count e.g. 12, Bend Range 48). Live: Preferences → MIDI → PolyBrute port **MPE = On**. Track MIDI From = PolyBrute, **All Channels**.
2. Right-click the Terrain device title bar → **Enable MPE Mode** (Live's manual says the MPE Settings exist for "plug-ins that do not officially support MPE but can be used with MPE controllers due to their multi-timbral support", §12.6). Check MPE Settings: Lower Zone, global channel 1, note channels 2-16.
3. What Terrain does today with that stream: every note plays (`appliesToChannel` true, `SynthVoice.h:38`); any finger's pressure hits **all** notes (`:7924` global); any per-note bend bends **all** notes at `SYN_BEND_RANGE` (2 st, not 48 — expect vibrato, not the PolyBrute's 48-st glide); CC74 does nothing unless MIDI-learned. If Max hears exactly that, Live is delivering channel-rotated MIDI to the AU and the design's host half is proven; if the notes stop arriving or only channel 1 plays, that is the Live/AU question to resolve first.
